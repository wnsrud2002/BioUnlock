Unlockface(얼굴 인식 언락, Swift + CoreML, 메뉴바 앱) 위에 손바닥 인증을
얹는 설계다. 요청서의 표준 스택(MediaPipe + Python + PAM) 중 네 가지를
뒤집었고, 그 근거를 §0에 먼저 둔다.

ENGINEERING.md에서 가져온 것이고, 손바닥 쪽 임계값과 상수는 전부
'출발점 추정치'다. 같은 방식으로 실측해서 교체해야 한다.

────────────────────────────────────────────────────────────────────────────────
1.1 손 검출 — Vision이 안 알려주는 것 하나
────────────────────────────────────────────────────────────────────────────────

VNHumanHandPoseObservation은 21점과 chirality(왼손/오른손)를 준다.
그런데 손바닥을 보는 중인지 손등을 보는 중인지는 알려주지 않는다.
오른손 손등은 왼손 손바닥과 2D 투영이 거의 같아서, 이걸 안 거르면
등록된 오른손 손바닥이 왼손 손등으로도 매칭될 여지가 생긴다.

판별법: 손등을 보면 랜드마크 좌표계의 방향(handedness)이 뒤집힌다.
새끼→검지 벡터와 손목→중지 벡터의 외적 부호 하나로 판정된다.

--- Sources/Unlockpalm/PalmDetector.swift (신규) -------------------------------

// Vision 은 chirality(왼손/오른손)만 준다. 손바닥/손등은 직접 판별해야 한다.
// 손등을 보면 2D 랜드마크 프레임의 방향이 뒤집히므로 외적 부호로 걸러진다.
//
// 부호는 반드시 실측으로 확정할 것 — 전면 카메라 미러링 여부,
// CVPixelBuffer 의 orientation 설정에 따라 통째로 뒤집힌다.
// (Unlockface Phase 1 에서 yaw/roll 부호로 똑같은 데 한 번 빠졌다.)
private let palmFacingSign: CGFloat = -1   // ← 실측 후 확정

static func isPalmFacing(_ p: PalmPoints, chirality: VNChirality) -> Bool {
    let across = CGPoint(x: p.indexMCP.x - p.littleMCP.x,
                         y: p.indexMCP.y - p.littleMCP.y)
    let along  = CGPoint(x: p.middleMCP.x - p.wrist.x,
                         y: p.middleMCP.y - p.wrist.y)
    let z = across.x * along.y - across.y * along.x
    let want = (chirality == .right) ? palmFacingSign : -palmFacingSign
    return z * want > 0
}

// 신뢰도 게이트: 21점 전부가 아니라 정렬에 쓰는 5점만 엄격하게 본다.
// 손가락 끝은 자주 가려지지만 MCP·손목은 거의 안 가려진다.
static let alignmentJoints: [VNHumanHandPoseObservation.JointName] =
    [.indexMCP, .middleMCP, .ringMCP, .littleMCP, .wrist]
static let minJointConfidence: Float = 0.7

────────────────────────────────────────────────────────────────────────────────
1.2 ROI 정규화 — 2점으로 풀면 잔차가 항상 0이 된다
────────────────────────────────────────────────────────────────────────────────

고전 팜프린트 ROI는 검지-중지 사이 골(V1)과 약지-소지 사이 골(V2),
두 점으로 좌표계를 세운다. Vision에는 골 점이 없으니 MCP 중점으로
근사하면 된다 — 여기까지는 표준이다.

!! 함정 !!
2점으로 유사변환(4자유도)을 풀면 미지수 4개에 방정식 4개라 항상 완벽하게
맞는다. 즉 FaceAligner.residual과 같은 정렬 자가진단이 구조적으로
불가능해진다. 손바닥은 얼굴보다 자세 변화가 훨씬 심한데, 품질 신호를
잃은 채로 들어가게 된다.

해결: MCP 4점 + 손목 = 5점을 쓴다. Unlockface가 얼굴 5점으로 만든 것과
같은 과결정 구조가 되어, 잔차가 다시 "자세 이상 + 검출 노이즈"의 통합
품질 지표로 살아난다. MCP 4점만 쓰면 거의 일직선이라 수직 방향으로
조건수가 나빠지니, 손목이 공선성을 깨는 역할도 겸한다.

정렬과 ROI 정의는 분리한다 — 5점으로 정준 손 프레임(192×192)을 만들고,
그 안에서 고정 사각형을 잘라 팜프린트 ROI로 쓴다. 나중에 ROI를 튜닝할 때
변환 코드를 안 건드려도 된다.

--- Sources/Unlockpalm/PalmAligner.swift (신규, 변환 함수는 UnlockKit 재사용) ---

enum PalmAligner {

    /// 정준 손 프레임 192×192, 원점 좌하단(CoreImage 규약 — FaceAligner 와 동일).
    /// 왼손은 입력 단계에서 좌우 반전해 넣으므로 정준 세트는 하나면 된다.
    ///
    /// 이 좌표는 출발점일 뿐이다. 등록 샘플 20장의 평균 정렬 잔차가 최소가
    /// 되도록 한 번 재추정하고, 그 값을 여기 박아 넣을 것.
    static let canonical192: [CGPoint] = [
        CGPoint(x: 146, y: 158),   // indexMCP
        CGPoint(x: 114, y: 164),   // middleMCP
        CGPoint(x:  82, y: 160),   // ringMCP
        CGPoint(x:  52, y: 146),   // littleMCP
        CGPoint(x:  98, y:  14)    // wrist
    ]

    /// 정준 프레임 안에서 실제로 매칭에 쓰는 팜프린트 영역.
    /// 손목 주름(변형 심함)과 손가락 밑동(가림 잦음)을 뺀 안쪽.
    static let roiInCanonical = CGRect(x: 44, y: 40, width: 112, height: 112)
    static let roiOutputSize = 128

    static func align(image: CIImage, points: PalmPoints, mirrored: Bool) -> CIImage? {
        let extent = image.extent
        var src = points.alignmentArray.map {
            CGPoint(x: extent.origin.x + $0.x * extent.width,
                    y: extent.origin.y + $0.y * extent.height)
        }
        if mirrored { src = src.map { CGPoint(x: extent.maxX - $0.x, y: $0.y) } }

        // UnlockKit 로 옮긴 FaceAligner 의 최소제곱 유사변환을 그대로 쓴다.
        guard let t = Geometry.similarityTransform(from: src, to: canonical192)
        else { return nil }

        let base = mirrored
            ? image.transformed(by: CGAffineTransform(scaleX: -1, y: 1)
                                     .translatedBy(x: -extent.maxX, y: 0))
            : image
        return base.clampedToExtent()
                   .transformed(by: t)
                   .cropped(to: roiInCanonical)
    }

    /// 팜프린트 고유 게이트: 원본에서 ROI 가 실제로 몇 픽셀이었나.
    /// 손바닥은 얼굴과 달리 '주름 텍스처'가 특징이라, 업샘플된 ROI 는 정보가 없다.
    /// 유사변환의 스케일 성분으로 역산한다.
    static func sourcePixelsPerROISide(_ t: CGAffineTransform) -> CGFloat {
        let scale = sqrt(t.a * t.a + t.b * t.b)   // 등방 스케일
        return roiInCanonical.width / scale
    }
    static let minSourcePixels: CGFloat = 160   // ← 실측으로 확정
}

■ 실측해야 하는 임계값 3개

Unlockface가 라플라시안 분산으로 블러 절벽(0.5~1.0px)을 찾아 인증 120 /
등록 300을 잡은 방식 그대로, 손바닥도 감으로 정하면 안 된다.

  - 정렬 잔차
    손바닥을 15°, 30°, 45° 기울여가며 5점 잔차를 재고, 임베딩 유사도가
    무너지기 시작하는 각도를 경계로.

  - ROI 원본 픽셀 수
    20cm / 30cm / 40cm / 50cm 거리에서 ROI 픽셀 수와 본인 점수를 같이
    재면 절벽이 보인다.

  - 선명도
    얼굴과 같은 방법이지만 임계값은 재측정. 128×128 손바닥 ROI의
    라플라시안 분산 스케일은 112×112 얼굴과 다르다.


────────────────────────────────────────────────────────────────────────────────
1.3 CLAHE — CoreImage에는 없고, vImage로 90줄
────────────────────────────────────────────────────────────────────────────────

CoreImage에 CLAHE 필터는 없다. 새 의존성 없이 하려면 Accelerate로 직접
짠다: 그레이스케일 ROI를 8×8 타일로 나눠 타일마다 히스토그램을 만들고,
클립 리밋으로 빈을 자른 뒤 잘린 양을 균등 재분배하고, CDF를 LUT로 굳힌
다음 픽셀마다 인접 4타일 LUT를 이중선형 보간한다.

vImageEqualization_Planar8은 전역 평활화라 그대로는 못 쓰지만,
타일별 히스토그램 계산에 vImageHistogramCalculation_Planar8을 쓰면 된다.

!! 함정 — SFace 이중정규화와 같은 종류 !!
전처리는 학습과 짝이다. CLAHE를 적용한 ROI로 학습한 모델에는 추론 때도
CLAHE를 넣어야 하고, 안 넣고 학습한 모델에 CLAHE를 넣으면 조용히 틀어진다.
SFace ONNX 그래프 안에 Sub/Mul이 이미 있어서 Swift에서 또 정규화하면
안 됐던 것과 정확히 같은 구조의 버그다.

CompCode(§1.4)를 쓰면 이 문제가 사라진다 — Gabor 응답의 argmin만 쓰기
때문에 밝기·대비에 원래 불변이라 CLAHE가 있어도 없어도 코드가 거의 안
바뀐다. v0.1에서 CLAHE를 선택 사항으로 두고, 학습 모델을 붙이는 v0.2에서
학습 파이프라인과 함께 고정할 것.


────────────────────────────────────────────────────────────────────────────────
1.4 특징 추출 — 여기가 진짜 리스크다
────────────────────────────────────────────────────────────────────────────────

얼굴에는 Apache-2.0 SFace가 있었다. 손바닥에는 그에 해당하는 게 사실상
없다. 공개 팜프린트 데이터셋은 거의 전부 "비상업적 연구 목적 한정"이고,
상당수는 파생 모델 재배포까지 명시적으로 제한한다. InsightFace 때 배포
직전에 발견한 것과 완전히 같은 지뢰다.

■ 권장 — v0.1은 학습 없이 출시

CompCode(Kong & Zhang, 2004)는 팜프린트에서 얼굴의 LBP와 위상이 다르다.
얼굴에서 고전 방식은 딥러닝에 완패했지만, 팜프린트에서는 고전 코딩 방식이
지금도 경쟁력이 있다 — 손금이라는 명확한 방향성 선 구조를 직접 인코딩하기
때문이다.

가중치 파일도, 데이터셋 약관도, ONNX→CoreML 변환 검증도 없이 v0.1을 낼 수
있고, 그동안 §1.7의 임계값 실측 인프라를 먼저 갖춰 놓을 수 있다.
학습 임베딩은 그 인프라 위에 얹으면 된다.

--- Sources/Unlockpalm/PalmMatcher.swift (v0.1 CompCode) ----------------------

// CompCode: 6방향(0°,30°,…,150°) Gabor 실수부 뱅크를 ROI 에 돌리고,
// 픽셀마다 '응답이 최소인 방향'의 인덱스를 코드로 삼는다.
// 손금은 주변보다 어두우므로 선 방향과 나란한 필터에서 응답이 최소가 된다.
//
// argmin 만 쓰기 때문에 밝기·대비 변화에 원래 불변이다 — 조명 강인성을
// 전처리가 아니라 표현 자체가 갖는다.

struct PalmCode {
    let bits: [UInt8]   // 128×128 각 픽셀당 3비트(0…5), 비트플레인 3장
    let mask: [UInt8]   // 유효 픽셀(ROI 안 + 응답 크기 충분)
}

/// 정규화 해밍 거리. 정렬 오차 흡수를 위해 ±3px 이동 탐색 후 최솟값.
/// 코사인 유사도와 방향을 맞추려면 1 - distance 를 점수로 쓴다.
static func score(_ a: PalmCode, _ b: PalmCode) -> Float {
    var best: Float = 1.0
    for dy in -3...3 {
        for dx in -3...3 {
            best = min(best, angularHamming(a, b, dx: dx, dy: dy))
        }
    }
    return 1 - best
}

// 방향 인덱스는 원형이다(0 과 5 는 30° 차이지 150° 차이가 아니다).
// 단순 XOR 해밍을 쓰면 이 wrap-around 를 놓쳐 조용히 성능이 깎인다.
private static func angularDiff(_ x: UInt8, _ y: UInt8) -> Float {
    let d = Int(x) - Int(y)
    return Float(min(abs(d), 6 - abs(d))) / 3.0
}

■ 불변 규칙 (Phase 4 버그 2의 교훈이 그대로 적용된다)

보안 게이트의 집계는 평균이 아니라 최소값.
신호가 셋(비강체 잔차 / 고주파 / 챌린지)이면 셋 중 최솟값,
프레임 5장이면 5장 중 최솟값, 창이 다 찰 때까지는 판정 보류.

평균을 쓰면 좋은 프레임 두 장이 나쁜 프레임 세 장을 구제해 준다 —
(0.99 × 2) / 5 = 0.396 으로 실제로 통과됐던 그 계산이다.

그리고 판정을 '못 한' 경우는 통과가 아니라 차단(fail-closed).
UnlockService.feed 가 이미 그렇게 짜여 있다.

1.6 잠금 해제 — 코드는 그대로, UX만 문제

■ 얼굴과 다른 점 — 피드백을 줄 수 없다

얼굴은 뚜껑을 열면 그냥 되지만, 손바닥은 사용자가 손을 들어 올려 프레임
안에 맞춰야 한다. 그런데 잠금화면은 SecurityAgent가 소유하고 있어서
그 위에 안내 오버레이를 띄울 수 없다(CGShieldingWindowLevel 위로
안정적으로 못 올라간다). 손이 프레임 밖인지, 너무 먼지, 손등을 보이고
있는지를 화면으로 알려줄 방법이 없다.

현실적인 답 두 개:

  1) 소리 피드백 — NSSound로 "손 감지됨" / "인식 성공"을 다른 톤으로.
     잠금 중에도 재생된다.

  2) 메뉴바에 연습 모드 — 잠금이 풀린 상태에서 실시간 ROI·품질 점수를
     보여주며 사용자가 적정 거리·각도를 몸으로 익히게 한다.
     이건 있으면 좋은 게 아니라 없으면 못 쓰는 기능이다.

--- scripts/fetch-models.sh (신규) --------------------------------------------

#!/bin/bash
# Models/ 를 채운다. 이미 있고 sha256 이 맞으면 아무것도 안 한다.
# package.sh 가 맨 앞에서 이 스크립트를 호출하도록 한 줄 추가할 것.
set -euo pipefail

ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
CACHE="$HOME/Library/Caches/tech.unlockface.models"
REPO="wnsrud2002/Unlockface"
TAG=$(/usr/bin/plutil -extract release_tag raw -o - "$ROOT/models/manifest.json")

mkdir -p "$CACHE" "$ROOT/Models"

count=$(/usr/bin/plutil -extract models raw -o - "$ROOT/models/manifest.json")
for i in $(seq 0 $((count - 1))); do
  file=$(/usr/bin/plutil -extract models.$i.file   raw -o - "$ROOT/models/manifest.json")
  want=$(/usr/bin/plutil -extract models.$i.sha256 raw -o - "$ROOT/models/manifest.json")
  dest="$ROOT/Models/${file%.zip}"

  # 이미 풀려 있으면 건너뛴다.
  [ -d "$dest" ] && { echo "skip  $file"; continue; }

  if [ ! -f "$CACHE/$file" ]; then
    echo "fetch $file"
    curl -fsSL --retry 3 -o "$CACHE/$file" \
      "https://github.com/$REPO/releases/download/$TAG/$file"
  fi

  # 검증 실패는 캐시를 지우고 즉시 중단한다. 조용히 넘어가면
  # 깨진 가중치로 빌드된 앱이 '인식률이 좀 낮네' 로 위장한다.
  got=$(shasum -a 256 "$CACHE/$file" | cut -d' ' -f1)
  if [ "$got" != "$want" ]; then
    rm -f "$CACHE/$file"
    echo "sha256 불일치: $file" >&2; exit 1
  fi

  ditto -x -k "$CACHE/$file" "$ROOT/Models"
  echo "ok    $file"
done

■ Intel 러너 관련

macos-13이 마지막 Intel 이미지이고 은퇴 수순이다. 그런데 매트릭스가

Intel 러너는 "Intel에서 실제로 실행되는가"를 테스트할 때만 의미가 있고,
ENGINEERING.md의 알려진 한계에 그게 미검증이라고 이미 적혀 있으니 —
Intel 러너가 살아 있는 동안 swift test만 거기서 한 번 더 돌려 그 한계를
지우는 게 실익이다.

2.4 릴리스 자동화 — TCC가 서명에 묶여 있다는 게 CI의 핵심 제약
────────────────────────────────────────────────────────────────────────────────

!! 함정 — 여기가 CI에서 제일 중요한 지점 !!

README에 이미 적어 둔 대로 카메라·키체인 권한은 코드 서명 식별자에
묶인다. CI가 릴리스마다 새 임시 인증서로 서명하면, 사용자가 업데이트할
때마다 카메라 권한을 다시 허용해야 하고 키체인의 등록 데이터에 접근을
못 하게 된다. "업데이트했더니 등록한 얼굴이 사라졌어요" 이슈가 그대로
열린다.

그래서 CI 서명 인증서는 고정이어야 한다. setup-signing.sh가 만드는 로컬
자체서명 인증서를 .p12로 내보내 base64로 시크릿에 넣고, 릴리스마다 같은
걸 임시 키체인에 임포트한다. Apple Developer ID($99/년)가 있으면 그걸
쓰고 공증까지 하면 우클릭 안내 자체가 사라진다.

먼저 package.sh가 CI에서 식별자를 받을 수 있게 3줄만 고친다:

--- scripts/package.sh 수정 — [4/5] 코드서명 블록 ------------------------------

-IDENTITY="Unlockface Dev"
+# CI 는 시크릿의 고정 인증서를 임시 키체인에 임포트하고 이 변수로 넘긴다.
+# TCC 권한이 서명 식별자에 묶이므로 릴리스마다 식별자가 바뀌면 안 된다.
+IDENTITY="${SIGN_IDENTITY:-Unlockface Dev}"

name: release
on:
  push:
    tags: ['v*']

  contents: write            # gh release create 에 필요

  release:
    runs-on: macos-15

      # 태그와 Info.plist 가 어긋난 릴리스를 만드는 건 되돌리기 가장 귀찮은 실수다.
      # 빌드 전에 실패시킨다.
      - name: 태그 ↔ Info.plist 버전 일치 확인
        run: |
          TAG="${GITHUB_REF_NAME#v}"
          PLIST=$(/usr/libexec/PlistBuddy -c "Print CFBundleShortVersionString" Resources/Info.plist)
          echo "tag=$TAG plist=$PLIST"

      - name: 고정 서명 인증서를 임시 키체인에 임포트

          CERT_PASSWORD: ${{ secrets.MACOS_CERT_PASSWORD }}
          KC_PASSWORD:   ${{ secrets.KEYCHAIN_PASSWORD }}
        run: |
          echo "$CERT_P12" | base64 --decode > "$RUNNER_TEMP/cert.p12"
          security create-keychain -p "$KC_PASSWORD" build.keychain
          security default-keychain -s build.keychain
          security unlock-keychain -p "$KC_PASSWORD" build.keychain
          security set-keychain-settings -lut 21600 build.keychain
          security import "$RUNNER_TEMP/cert.p12" -k build.keychain \
            -P "$CERT_PASSWORD" -T /usr/bin/codesign
          # 이게 없으면 codesign 이 GUI 암호 프롬프트를 띄우려다 러너에서 멈춘다.
          security set-key-partition-list -S apple-tool:,apple:,codesign: \
            -s -k "$KC_PASSWORD" build.keychain
          rm -f "$RUNNER_TEMP/cert.p12"

      - name: 모델 가져오기
        run: ./scripts/fetch-models.sh

      - name: 유니버설 빌드 + 서명 + ZIP
        env:

        run: ./scripts/package.sh

      # Developer ID 가 있을 때만. 없으면 통째로 건너뛰고
      # README 의 우클릭 안내가 유효하다.
      - name: 공증 + 스테이플
        if: ${{ secrets.NOTARY_APPLE_ID != '' }}

          AC_ID:   ${{ secrets.NOTARY_APPLE_ID }}

          xcrun notarytool submit "build/Unlockface-$V.zip" \
            --apple-id "$AC_ID" --team-id "$AC_TEAM" --password "$AC_PWD" --wait
          # 스테이플은 .app 에 찍고 나서 다시 압축해야 한다. ZIP 에는 못 찍는다.
          xcrun stapler staple build/Unlockface.app
          ditto -c -k --keepParent build/Unlockface.app "build/Unlockface-$V.zip"
          spctl -a -vvv -t install build/Unlockface.app

      - name: 체크섬
        run: cd build && shasum -a 256 *.zip > SHA256SUMS.txt

      - name: 릴리스 생성
        env: { GH_TOKEN: ${{ github.token }} }

          gh release create "$GITHUB_REF_NAME" \
            --title "$GITHUB_REF_NAME" --generate-notes \
            build/*.zip build/SHA256SUMS.txt

      # Homebrew tap 저장소의 cask 를 자동으로 올린다.

      - name: Homebrew cask 버전 올리기

        env: { GH_TOKEN: ${{ secrets.TAP_TOKEN }} }
        run: |
          V="${GITHUB_REF_NAME#v}"
          SHA=$(shasum -a 256 "build/Unlockface-$V.zip" | cut -d' ' -f1)
          gh api repos/wnsrud2002/homebrew-tap/dispatches \
            -f event_type=bump \
            -F "client_payload[version]=$V" \
            -F "client_payload[sha256]=$SHA"

!! 먼저 — 자동 권한 부여는 불가능하다 !!

요청서의 "설치 스크립트가 TCC 권한을 자동 등록"은 MDM 없이는 원리적으로
안 된다. tccutil은 reset만 있고 grant가 없다. TCC 데이터베이스는 SIP로
보호되고, 쓰려면 그 자체로 전체 디스크 접근 권한이 필요하다(닭과 달걀).

가능한 건 셋뿐이다:
  1) 정확한 설정 패널로 딥링크를 열어 주기
  2) 현재 권한 상태를 앱 안에서 확인해 체크리스트로 보여주기
  3) 로그인 항목은 SMAppService로 실제 자동 등록

설치 스크립트는 파일 배치와 격리 속성 제거까지만 하고, 권한 안내는 앱이
하는 게 맞다 — SettingsView.swift가 이미 그 방향이다.

--- scripts/install.sh (신규) --------------------------------------------------

#!/bin/bash
# curl -fsSL https://raw.githubusercontent.com/wnsrud2002/Unlockface/main/scripts/install.sh | bash
set -euo pipefail

REPO="wnsrud2002/Unlockface"
APP="/Applications/Unlockface.app"
TMP=$(mktemp -d); trap 'rm -rf "$TMP"' EXIT

[ "$(uname -s)" = Darwin ] || { echo "macOS 전용입니다." >&2; exit 1; }
[ "$(sw_vers -productVersion | cut -d. -f1)" -ge 13 ] \
  || { echo "macOS 13 이상이 필요합니다." >&2; exit 1; }

echo "[1/4] 최신 릴리스 확인"
URL=$(curl -fsSL "https://api.github.com/repos/$REPO/releases/latest" \
      | grep -o '"browser_download_url": *"[^"]*\.zip"' | head -1 | cut -d'"' -f4)
SUMS=$(curl -fsSL "https://api.github.com/repos/$REPO/releases/latest" \
      | grep -o '"browser_download_url": *"[^"]*SHA256SUMS.txt"' | head -1 | cut -d'"' -f4)
[ -n "$URL" ] || { echo "릴리스를 찾지 못했습니다." >&2; exit 1; }

echo "[2/4] 내려받기 + 체크섬 검증"
curl -fsSL --retry 3 -o "$TMP/app.zip" "$URL"
curl -fsSL -o "$TMP/SHA256SUMS.txt" "$SUMS"
WANT=$(grep -o '^[0-9a-f]\{64\}' "$TMP/SHA256SUMS.txt" | head -1)
GOT=$(shasum -a 256 "$TMP/app.zip" | cut -d' ' -f1)
[ "$WANT" = "$GOT" ] || { echo "체크섬 불일치 — 설치를 중단합니다." >&2; exit 1; }

echo "[3/4] /Applications 에 설치"
# 실행 중이면 먼저 종료. 안 그러면 교체된 바이너리와 실행 중 프로세스가 어긋난다.
osascript -e 'quit app id "tech.unlockface.app"' 2>/dev/null || true
ditto -x -k "$TMP/app.zip" "$TMP/out"
rm -rf "$APP"
ditto "$TMP/out/Unlockface.app" "$APP"
# curl 은 격리 속성을 안 붙이지만, 만약을 위해 한 번 더 지운다.
xattr -dr com.apple.quarantine "$APP" 2>/dev/null || true

echo "[4/4] 권한 안내"
open "$APP"
cat <<'EOS'

설치가 끝났습니다. 남은 건 직접 허용해야 합니다
(TCC 권한은 MDM 없이 스크립트로 부여할 수 없습니다):

  1. 카메라      — 시스템 설정 > 개인정보 보호와 보안 > 카메라
  2. 손쉬운 사용 — 시스템 설정 > 개인정보 보호와 보안 > 손쉬운 사용
     (잠금화면에 비밀번호를 대신 입력하는 데 반드시 필요합니다)

메뉴바 아이콘 > 설정… 에서 두 권한의 현재 상태를 확인하고
해당 설정 패널을 바로 열 수 있습니다.
EOS

# Unlockface

배지 · 한 줄 소개
"생체인증이 아니라 자동화" 경고            ← 그대로. README 의 핵심 자산.

## 기능
+ 손바닥 인식으로 잠금 해제 (Vision HandPose + CompCode)
+ 얼굴·손바닥 둘 다 통과해야 해제하는 2요소 모드

## 요구 사항                                ← 그대로

## 설치
+ ### Homebrew (권장)
+   brew install --cask --no-quarantine wnsrud2002/tap/unlockface
+ ### 설치 스크립트
+   curl -fsSL https://raw.githubusercontent.com/…/install.sh | bash
  ### 직접 내려받기                          ← 기존 우클릭 안내를 여기로 강등
  ### 소스에서 빌드                          ← fetch-models.sh 한 줄 추가

## 처음 설정하기
+ 손바닥 등록: 거리·각도 안내, "연습 모드" 설명
+ ⚠ 잠금화면에는 안내 화면을 띄울 수 없으므로 소리로 피드백한다는 설명

## 문제 해결                                 ← 신규 섹션
+ 손을 들어도 반응이 없음 → 거리 25~40cm, 손바닥이 카메라를 향하는지
+ 업데이트 후 카메라 권한을 다시 물어봄 → 서명 식별자 변경, 이슈로 보고
+ "손상되었거나 확인할 수 없음" → xattr -dr com.apple.quarantine
+ 인식은 되는데 잠금이 안 풀림 → 손쉬운 사용 권한, 비밀번호 재저장

## 보안 모델과 한계                          ← 손바닥 실측치를 같은 형식으로 추가
+ 손바닥 임계값 근거: 타인 세트·최고 유사도·분리 여유
+ ⚠ 손바닥 Liveness 는 무엇을 검증했고 무엇을 안 했는지 명시

## 라이선스
+ 손바닥 모델/데이터셋 출처와 약관을 THIRD_PARTY_LICENSES.md 에 추가
